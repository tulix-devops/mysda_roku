## Notes
- **Race walk (prompt item 2).** Apart from N1's guard, I found no way for a ghost, a stale code, or a "too long" or "No link" note to sit beside another church's name:
  - showChurch clears the modules and `qrFor` first (:267-268).
  - It hides `qrNote` on every code path (:306) and replaces its text on the empty path (:302).
  - The loader is shown only on the uncached path, after the modules are cleared (:314). It is hidden by a draw (:392), by "too long" (:367) and by the empty path (:301).
  - The cached path draws synchronously, so no timer is left armed (it was stopped at :299).
  - Holding Down through uncached churches keeps restarting the timer, with the loader already on (`showLoader` returns early when its state is unchanged, :319).
  - FIFO eviction can never remove the link being drawn, because the evict-then-insert happens inside the same drawQr call, and the code drawn comes from the local `q`.
  - An empty or non-http link stops the timer before its early return (:299-305).
  - A too-long link (over 213 bytes) is rejected cheaply in ScQrMatrix before any matrix work (ScQr.brs:24-35). It is not cached, so a later visit shows the ghost again for 0.25 s and then the note.
- **Reserved words (prompt item 3).** I grepped ScChurches.brs, ScChurchTask.brs and ScQr.brs for the reserved and builtin family (`run pos box tab step rem sub mod type eval stop goto dim let next exit print end line_num objfun`) and for single-word builtins (`log int str val string left right len mid chr asc abs sgn rnd wait sleep exp sqr fix tr instr ucase lcase`). I checked them as assignment targets, loop variables, parameters and function names. Hits:
  - `for each at` (:42) and the parameter `on` in `showLoader(on as boolean)` (:318). Neither is a BrightScript reserved word or builtin.
  - A local `right` (ScQr.brs:135, 149), which shadows `Right()` inside ScQrMatrix only. It was noted in review 1, it compiles on the device, and `Right()` is not called in that function. hostIs's `Right()` (:351) is in another function, so it is unaffected.
  - The `run` loop variable is now `seg` (:384).
  - No other collisions. As [[reserved-words-and-name-collisions]] warns, `run` is the fourth repo's hit of the same family. Neither check-scope nor this repo's bsc run flagged it, and [[static-component-scope-check-script]] (summary) says check-scope flags `run` only in wpa_live_roku's copy. That makes a pre-deploy grep for the family worth adding to this repo.
- **Was the pinned build the one on the device?** ScChurches.brs was last written at 00:19:21. Capture 09 (00:19:06) is older than that, and capture 10 (00:20:12) is newer. 10 is therefore the only capture that can show the pinned .brs, and that holds only if a sideload happened in the 50 s between. The report does not log the deploy. Round 2 also does not say whether check-scope or bsc was re-run after the loader and the fixes.
- Learnings candidate: a host check that cuts the authority at `:` before handling `@`, and ignores `\`, is fooled by `https://youtube.com:x@evil.example/` and `https://evil.example\.youtube.com/`. Any "which site does this link open" label (QR hints, deep-link allowlists) needs the WHATWG order: strip userinfo, then the port, and treat `\` as `/` for http(s).
